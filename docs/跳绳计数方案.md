# 跳绳计数方案

> 目标：在浏览器里把一段跳绳视频拆成「次数、每分钟次数、跳高、节奏一致性、断绳区间」，
> 视频不上传，姿态识别在本机跑。

## 1. 和投篮模块的关系

跳绳和投篮共用同一套 MediaPipe Pose Landmarker（`prototype/js/pose-engine.js` 负责加载），
但计数算法完全独立，放在 `prototype/js/rope-engine.js`：

- 共用：模型、wasm 运行时、取帧函数、时间戳分配器；
- 不共用：投篮的出手检测、球轨迹、八项指标、评分体系。

这样做的好处是用户第一次打开页面时只下载一份约 19MB 的模型，两个项目都能用；
坏处是两个模块必须共用同一个检测器，所以 MediaPipe 要求的「时间戳严格递增」由
`acquireTimeBlock()` 统一分配，不能让两个模块各自从 0 开始数。

## 2. 计数流程

```
视频
  │
  ▼
按 30fps 抽帧（长视频自动降采样，上限 3600 帧）
  │
  ▼
PoseLandmarker 逐帧输出 33 个关键点
  │
  ▼
肩 / 髋 / 踝纵向位置
  │
  ▼
肩髋中点 = 主信号；脚踝离地 = 辅助信号
  │
  ▼
用站立身体跨度归一化 → 抵消身高和机位远近
  │
  ▼
补短缺口 → 重采样到 30Hz → 去慢趋势
  │
  ▼
峰值检测（自适应噪声阈值 + 突出度 + 最小间隔 + 峰后回落）
  │
  ▼
次数 / 每分钟次数 / 跳高 / 节奏 / 断绳
```

### 2.1 为什么用肩髋中点，而不是只看脚踝

跳绳时脚踝会离地，但脚踝也是最容易被绳子、裤脚和画面边缘干扰的点。
肩和髋是躯干上的大关节，稳定性更好；人整体向上跳时，肩髋中点会同步上移。

脚踝仍然有用：它负责回答「这次到底离地多高」。所以：

- **计数**用肩髋中点，抗干扰；
- **跳高**用脚踝相对站立基线的抬升，直观。

### 2.2 归一化

不同身高、不同机位距离，像素位移完全不可比。这里用「站立时鼻尖到脚踝的跨度」
作为尺子：

```
身体比例 = 纵向位移 / 站立跨度
```

鼻尖到踝的跨度约为身高的 0.891 倍（Drillis & Contini 的人体测量学比例），
所以厘米换算为：

```
cmPerUnit = 身高cm / (站立跨度 / 0.891)
跳高cm   = 脚踝抬升 × cmPerUnit
```

站立跨度取全片 85 分位，而不是最大值：跳跃时腿会收，最大值反而可能是
「腿收得最紧」的那一帧。

### 2.3 峰值检测

最初试过「信号必须先落回 0 再重新起飞」的状态机，但快速连跳时两次起跳之间
脚只着地一两帧，20–30fps 的采样很容易正好错过，信号不会回到基线，状态机就会
把连续几跳吞掉。

现在先把信号整理成适合找峰的形状，再做判据：

1. **补短缺口**：MediaPipe 偶尔一两帧识别不到，不补洞会让「局部极大」判断失效，
   在上升沿多造出假峰。只补 ≤0.35 秒的缺口，人出画/切镜头不补。
2. **重采样到 30Hz**：跳绳腾空段只有 0.15–0.3 秒。长视频采样率降到 12fps 时，
   按「帧」做 3 点平滑会横跨整个腾空段，把峰值抹平（实测 3 分钟视频会漏计 1/3）。
   统一重采样后，平滑窗口固定在 0.1 秒，计数不再受抽帧率影响。
3. **去慢趋势**：减掉 2.5 秒滚动中位数。人会前后走动、镜头会慢慢漂，
   全局基线会被这些慢变化带偏；去趋势后阈值和站位远近无关。
4. **自适应阈值**：`enter = max(0.0035, 3×噪声估计, 0.28×稳健幅度)`。
   噪声用二阶差分中位数估计；稳健幅度用 |去趋势信号| 的 90 分位，
   不会被一次特别高的起跳或镜头抖动拉高。
5. **峰值判据**：
   - 严格局部极大，且峰值高于 `enter`；
   - 峰前/峰后 0.3 秒内要有明显低点，突出度至少 `max(0.55×enter, 0.16×幅度)`；
   - 峰后 1 秒内必须往下掉 `max(0.45×enter, 0.35×突出度)`，证明人已经落地；
   - 两次峰至少隔 0.18 秒，防止同一次起跳被数两下；
   - 幅度低于本段中位数 12% 的候选直接丢弃；低于 45% 的保留，但标成「幅度偏低」。

这样既能接住快速连跳和低幅度起跳，也不会把走路、站立抖动数成跳绳。

### 2.3.1 跳高的局部基线

脚踝离地高度不再用全片一个固定基线。人走近镜头、镜头慢慢漂，都会让
「站着」在画面里的位置整体移动。现在每次起跳取前后 1.5 秒内脚踝信号的
25 分位作为这一跳附近的地面，再算脚踝峰值相对它的抬升。

### 2.4 每分钟次数

用相邻起跳间隔的中位数，而不是「总次数 ÷ 总时长」：

```
cadence = 60 / median(间隔)
```

中位数对中途停顿不敏感。中途停 10 秒再跳，总时长法会把每分钟次数拉低，
但中位间隔仍然是真实跳绳节奏。界面同时给出「整体次数/分」作为对照。

### 2.5 节奏一致性

取 0.18–2.5 秒之间的有效间隔，算变异系数：

```
CV = 标准差 / 均值
score = clamp(100 - CV × 180 - 断绳次数 × 1.5, 0, 100)
```

少于 3 个完整间隔时不给分，避免「只跳了两下，节奏 100 分」这种假精确。

### 2.6 断绳 / 幅度骤降

两类事件分开标：

- **停顿**：相邻两次起跳间隔超过 `max(0.9s, 2 × 中位间隔)`；
- **幅度骤降**：连续两次以上起跳幅度低于本段中位数 45%。

它们会画在时间轴的浅色区间里，并在小结卡片里列出来，点击可跳到对应时间。

## 3. 界面

- 左列：视频、时间轴、逐帧/播放控制、跳跃记录表；
- 右列：四张指标卡、本段小结、纵向节奏曲线、拍摄建议；
- 时间轴：橙色竖线 = 正常起跳，琥珀色 = 幅度偏低，浅色带 = 停顿/骤降；
- 播放时骨架叠加，并用圈标出当前这次起跳；
- 改身高只线性缩放厘米值，不重跑模型。

## 4. 已知局限

- 人物占画面高度低于 40% 时，跳高换算误差明显，界面会提示；
- 脚踝经常出画时，跳高和计数都可能漏，界面会给出出画比例；
- 视频超过约 2 分钟时采样率开始下降：3 分钟约 20fps、4 分钟约 15fps，
  4 分钟以内计数仍然可靠；超过约 5 分钟会低于 15fps，快速连跳可能漏计，界面会提示分段拍摄；
- 算法不识别真实绳体，只根据身体纵向周期计数，因此「空手模仿跳绳」、原地小跑也会被计数；
- 站着不动时的 landmark 抖动已经用噪声阈值压掉，但抖动特别大（人物很小/光线很差）时仍可能出现零星假计数；
- 镜头晃动、人物前后走动会污染纵向信号，建议固定机位；慢漂移和走动已用滚动去趋势抵消。

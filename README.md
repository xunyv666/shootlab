# ShootLab · 投篮动作分析

***网站链接***: https://shootlab-pro.pages.dev/

浏览器里跑的运动动作分析工具。上传一段视频，它会逐帧识别人体姿态，
把动作拆成可量化的指标并给出可执行的改法。目前有三个项目：

- **投篮**：一次出手拆成 8 项指标，和 NBA 球员基准对照；
- **跳绳**：次数、节奏、跳高、断绳区间；
- **立定跳远**：距离、起跳角、蹬伸时序、摆臂、落地稳定性。

**视频不上传。** 姿态识别用的是 MediaPipe Pose，模型随页面加载到本地运行，
整段视频不进任何服务器，断网也能分析。

---

## 能做什么

| 功能 | 说明 |
|---|---|
| 出手检测 | 从整段视频里自动找出每一次出手，一段 30 秒的连续投篮训练能挑出 9–10 次 |
| 八项指标 | 出手角、肘部对位、出手点高度、起跳弹速、出手节奏、躯干稳定、随球、下肢发力 |
| 时间轴联动 | 拖动进度条，右侧指标实时切换到「那一刻」的读数，并标明是第几次出手 |
| 标准姿势模板 | 按人体测量学比例现算一副火柴人，叠加在你身上做对照 |
| 手动修正出手点 | 抬手被误判成出手时，把视频停在真正出手的那一帧，一键重算全部指标 |
| 点位打法 | 篮下 / 近距 45° / 中距 45° / 罚球线 / 弧顶三分 / 底角，每个点的打板角度与瞄准点不同 |
| 进球概率 | 出手前给概率：球路物理反解 + 姿势评分，缺出手角时如实标低置信 |
| 自我校准 | 标记每次进没进，命中结果回流后用 Platt scaling 校正概率，样本越多越准 |
| 教练讲解 | 逐次出手分段圈画讲解，语音朗读 + 现场合成的背景和声 |

## 跳绳计数

同一套本地姿态模型，换一个项目就是跳绳计数。算法在 `prototype/js/rope-engine.js`，
不复制任何第三方项目代码，思路与许可证说明见 [`docs/跳绳计数方案.md`](docs/跳绳计数方案.md)。

| 指标 | 说明 |
|---|---|
| 总次数 | 按「离地 → 最高点 → 落地」的完整起跳周期计数，带 0.18 秒最小间隔防重复 |
| 每分钟次数 | 用相邻起跳间隔的中位数算，中途停顿不会把节奏拉低 |
| 平均跳高 | 脚踝相对站立基线的抬升，按身高换算成厘米 |
| 节奏一致性 | 起跳间隔的变异系数，越稳分越高；少于 3 个间隔不给分 |
| 断绳 / 骤降 | 间隔突然变长、或连续起跳幅度明显变小，单独标在时间轴上 |
| 跳跃记录 | 每次起跳的时间、间隔、跳高，点击跳到视频对应位置 |

跳绳页同样在浏览器本地跑，视频不上传。固定机位、全身入镜、人物占画面一半以上时最准；
算法不识别真实绳体，只根据身体纵向周期计数。4 分钟以内的视频会按至少 15fps 采样，计数稳定。

## 立定跳远

同一套本地姿态模型，再换一个项目就是立定跳远测量。算法在
`prototype/js/longjump-engine.js`，界面在 `prototype/js/longjump.js`，
设计取舍与误差来源见 [`docs/立定跳远方案.md`](docs/立定跳远方案.md)。

| 指标 | 说明 |
|---|---|
| 跳跃距离 | 起跳帧脚尖 x → 落地帧脚跟 x，正好对上「量到最近触地点」的正式量法 |
| 起跳角 | 对腾空段重心轨迹做抛物线拟合，取起跳时刻的速度方向；理想 32–45°，峰值 38° |
| 腾空时间 / 最高点 | 由离地信号的过零点定；最高点用拟合初速度反算 `v²/2g`，不受起跳时刻误差放大 |
| 蹬伸时序 | 髋/膝/踝角度峰值的先后，峰顶做亚帧抛物线插值；间隔 <20ms 时如实报「分不出先后」而不是编顺序 |
| 摆臂配合 | 手臂前摆峰值与起跳时刻的时差、摆幅 |
| 落地稳定性 | 是否后移、手有没有撑地、膝关节缓冲够不够 |
| 标尺校准 | 在画面里点出卷尺两端并填真实长度，比按身高换算更准，顺手校掉一点透视 |
| 多跳记录 | 一段视频连跳多下时逐跳列出，默认展示最远的那一跳，点击跳到对应位置 |

比例尺有两条路：画面里有卷尺就用标尺校准，没有就用身高换算
（鼻尖→踝 ≈ 0.891 身高，与投篮/跳绳同口径）。改身高或重新点标尺只调
`applyScale()`，不重跑姿态模型。

**拍摄要求**：正侧面机位、镜头垂直对着跳跃方向、起跳线和落地区都在画面里、双脚全程不出画。
斜拍会把水平距离压扁，这个误差算法补不回来 —— 界面会如实标注，而不是给一个看起来很精确的假数字。

## 本地运行

页面用 ES module 加载姿态模型，**必须通过 http 打开**，双击 `index.html` 不行。

```bash
npm run serve          # 或：python tools/serve.py 8931 prototype
# 然后打开 http://127.0.0.1:8931/index.html
```

Windows 下也可以直接双击 `启动预览.bat`。

## 开发

`prototype/` 无构建步骤，改完 JS 刷新页面即可。仓库自带的质量检查：

```bash
ruff check tools               # Python lint（配置在 pyproject.toml）
for f in prototype/js/*.js; do node --check "$f"; done   # 全量语法检查（CI 同款）
node --check prototype/js/rope-engine.js
node --check prototype/js/longjump-engine.js
node --check prototype/js/longjump.js
```

立定跳远模块另有两套离线校验（改算法或界面后跑一遍）：

```bash
node _verify/gen.mjs         # 合成真值场景 + 蹬伸判定分支，不需要浏览器
node _verify/check-page.mjs  # 无头 Edge 打开页面做 DOM 断言与截图
```

## 部署

`prototype/` 是一个纯静态站点，所有资源路径都是相对的，
整个目录放到任意子路径下都能跑，不依赖后端。

- **Cloudflare Pages（自动）**：仓库已带 `.github/workflows/deploy.yml`，
  推到 `main` 即部署到 Cloudflare Pages 两个项目
  （`shootlab-pro` 对外地址 + `shootlab` 旧地址）。
  需要 Secrets：`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`
- **Cloudflare Pages（手动）**：`bash tools/deploy.sh`（需先 `wrangler login`）
- **其它静态托管**：把 `prototype/` 上传到站点子目录即可
- 注意服务端要能正确返回 `.wasm` 的 MIME 类型（`application/wasm`），
  否则姿态模型加载失败（`tools/serve.py` 本地已处理）

## 指标是怎么来的

八项指标的理想区间不是拍脑袋定的，是拿 5 位 NBA 球员（库里、汤普森、杜兰特、
布克、利拉德）的投篮逐帧测出来再换算成「÷身高」的比值，区间下限放宽以容纳业余球友。

出手角用 Brancazio 的最优出手角公式 `θ = 45° + ½·atan((篮筐高 − 出手点高) / 水平距离)`，
再用抛物线反解出手速度与入筐角。打板入射角在**水平面**上算：
`atan2(|横向偏移|, 到篮板面距离)` —— 不是和竖直方向的夹角。

## 已知局限

- 人占画面高度低于 40% 时，厘米类指标（出手点、起跳）误差明显，界面会标红提示
- 球出手后很快飞出画面的机位，测不出出手角，此时概率预测只用姿势，置信度会标低
- 单目视频没有深度信息，球员前后走动会让人物尺度估计抖动，同一个人不同出手的
  出手点会有 ±20cm 的测量噪声
- 摄像头建议：横屏、全身入画、球出手后仍在画面里、机位不要跟着人晃
- 立定跳远斜着拍会把水平距离压扁（可能少算 5–15%）；30fps 下髋/膝/踝的峰值
  常常挤在一帧内，此时只报「分不出先后」，不报顺序 —— 想看时序细节要用 60fps 或慢动作

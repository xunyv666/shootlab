# 立定跳远测量方案

> 目标：上传一段立定跳远视频，在浏览器本地算出「距离、起跳角、蹬伸时序、摆臂配合、落地稳定性」，
> 视频不上传，姿态识别在本机跑。

## 1. 和投篮 / 跳绳模块的关系

三个项目共用同一个 MediaPipe Pose Landmarker（`prototype/js/pose-engine.js` 负责加载），
但算法各写各的，互不引用：

| 模块 | 算法文件 | 界面文件 |
|---|---|---|
| 投篮 | `pose-engine.js`（内含出手检测与八项指标） | `app.js` 内的篮球面板 |
| 跳绳 | `rope-engine.js` | `rope.js` |
| 立定跳远 | `longjump-engine.js` | `longjump.js` |

- **共用**：模型、wasm 运行时、`seekTo()` 取帧、`acquireTimeBlock()` 时间戳分配器；
- **不共用**：起跳/落地检测、距离测量、评分体系。

MediaPipe 的 `VIDEO` 模式要求时间戳严格单调递增，两个模块各自从 0 开始数会直接抛错，
所以时间戳由 `acquireTimeBlock()` 统一发号。这是三个模块之间唯一的强耦合点。

## 2. 测量流程

```
视频
  │
  ▼
按 30fps 抽帧（上限 3600 帧；长视频自动降采样）
  │
  ▼
PoseLandmarker 逐帧输出 33 点（失败时围绕髋部裁剪 0.66×0.66 重试）
  │
  ▼
脚尖 y / 脚跟 y → 减站立基线 → 除以站立跨度 → 归一化「离地量」
  │
  ▼
重采样到 30Hz（低帧率视频也能用固定 0.1s 窗口平滑）
  │
  ▼
判定信号 = min(脚尖离地量, 脚跟离地量)
  │
  ▼
自适应阈值过零 → 腾空段 [t0, t1]
  │
  ▼
距离 / 起跳角 / 腾空高度 / 蹬伸时序 / 摆臂 / 落地
  │
  ▼
比例尺（标尺 or 身高）→ 厘米 → 评分
```

## 3. 为什么用 `min(脚尖, 脚跟)`

立定跳远的正式量法是「从起跳线量到落地区最近的身体触地点」。落到帧上就是：

- **起跳点**：脚尖离地那一刻 —— 脚尖是最后离开地面的部位；
- **落地点**：脚跟触地那一刻 —— 脚跟是最先接触地面的部位。

取两者离地量的较小值，等于「脚尖和脚跟都离地才算腾空」，
于是同一条信号的两个沿自然对应这两个时刻，不需要额外判断谁先谁后：

```
离地量
  │        ╱‾‾‾‾‾╲
  │      ╱         ╲
──┼────╱───────────╲──────  阈值
  │  ╱               ╲
  └──┴───────────────┴──→ t
    t0(脚尖离地)   t1(脚跟触地)
```

## 4. 关键参数

| 参数 | 值 | 理由 |
|---|---|---|
| 采样帧率 | 30fps | 腾空只有 0.4–0.6 秒，低于 30fps 抛物线拟合会飘 |
| 处理帧率 | 30Hz（重采样） | 低帧率视频也能用固定 0.1s 平滑窗口 |
| 站立跨度 | 鼻尖→踝的 85 分位 | 中位数会把尺子定短（跳跃时腿会收） |
| 脚部基线 | y 的 70 分位 | 取最大值会被一次深蹲拉低 |
| 离地阈值 | `max(0.012, 3σ)` | σ 由二阶差分中位数估（≈1.65σ），站着不动不会被切碎 |
| 最短腾空 | 0.16 秒 | 低于这个值多半是噪声抖动 |
| 身高换算 | 鼻尖→踝 ≈ 0.891 身高 | Drillis & Contini，与投篮/跳绳同口径 |
| 重力自检 | 981 cm/s² | 只做比例尺自检，不参与测量 |

## 5. 亚帧定位

30fps 一帧 33ms，直接取「第一个超过阈值的采样点」会有系统性滞后。
所以起跳/落地时刻分两步定：

1. 在相邻两点间线性插值，找到跨过阈值的时刻；
2. 在过零点附近取 3 点做直线拟合，外推到 `离地量 = 0`。

第 2 步很关键：信号是斜坡上升的，用阈值插值得到的是「到达阈值」的时刻，
不是「离地」的时刻。阈值压到 1.8cm 只是把误差压小，外推才是把它消掉。

合成场景实测：真值 2.000s，未外推时 2.013s，外推后 1.994s。

## 6. 距离与起跳角

**距离** = 起跳帧脚尖 x → 落地帧脚跟 x，乘以 `cmPerX`：

```
distN = |x_heel(t1) − x_toe(t0)|
distCm = distN × cmPerX
```

方向 `dir = sign(x1 − x0)`，向左跳时为 −1。所有涉及「前/后」的量都乘 `dir`，
避免代码里隐含「向右为正」的假设 —— 手机横拍翻转一下就会翻车。

**起跳角** 不直接取两帧位移（噪声太大），而是：

1. 对腾空段重心轨迹拟合 `y = a·t² + b·t + c`；
2. 对髋部水平位移拟合直线 `x = k·t + m`；
3. 在 `t0` 处取速度：`vy = 2a(t0 − tm) + b`，`vx = k × ar`；
4. `θ = atan2(−vy, |vx|)`。

`ar` 是画面宽高比：归一化坐标里 x 和 y 的单位长度不一样，不换算角度会系统性偏小。

**腾空高度** 用拟合初速度反算 `h = vy² / (2g)`，而不是「最高点 − 起跳点」。
起跳时刻早判几毫秒，后者的误差会被直接放大，前者不会。

**等效重力自检**：`g_implied = 2a × 画面高 / 每厘米像素数`。
真实值 981 cm/s²，偏出 ±150 就在界面上提示「比例尺可能不准」。

## 7. 蹬伸时序：不假装能分辨

标准动作是近端到远端：**髋 → 膝 → 踝**。顺序反了（膝比髋早）意味着力量没经过髋，
是跳不远最常见的原因。

问题在于 30fps 一帧就有 33ms，三个关节的角度峰值经常落在同一帧，
`argmax` 取出来就是三个一模一样的数字，顺序全靠数组顺序碰运气 ——
看起来精确，其实是编的。

处理方式：

1. 对峰顶做三点抛物线插值，把时刻细化到亚帧：
   `u = 0.5·(y₀ − y₂) / (y₀ − 2y₁ + y₂)`，`t = t(bi) + u·Δt`；
2. 三个峰值的极差 `< 20ms` 时判为 `extTie`（采样精度内分不开），
   **不输出顺序结论**，评分给中性 70 分；
3. 只有极差 ≥ 20ms 才判 `ok` / `reversed`。

结论由 `extVerdict(j)` 统一给出（`'ok' | 'reversed' | 'tie' | null`），
评分和界面都从这里取，避免两边各判一次、说法不一致。

> 合成场景里髋、踝由同一个 2 连杆模型解出，三段天然同时伸展，
> 引擎如实判成 `tie` —— 这比报一个「髋→膝→踝」更接近事实。

## 8. 摆臂与落地

**摆臂**：起跳窗口 `[t0 − 0.9, t0 + 0.5]` 内找 `dir × 手臂前摆角` 的峰值，
记 `armLag`（相对起跳的毫秒数）与 `armAmp`（摆幅）。理想是峰值落在起跳前后 ±120ms。

**落地稳定性** 三个量：

| 量 | 判据 | 说明 |
|---|---|---|
| 后移 | `dir × (x_hip(落地) − x_hip(落地+0.6s))` | 正 = 往起跳方向的反方向退，成绩按最靠后的触地点算 |
| 手撑地 | 手腕与脚跟高差 `< 0.18 × 站立跨度`（约 28cm） | 只查落地之后，否则起跳前的下蹲摆臂会被误判 |
| 最低膝角 | 落地后 0.45s 内膝角最小值 | `>160°` 直腿落地，冲击全给关节 |

手撑地的判据不能写「手低于膝」：深蹲时膝盖本身就很低，那个条件会漏掉真正撑地的动作。
也不能把符号写反 —— 画面 y 向下为正，手比脚跟高时算出来是负值，
所以是 `> −0.18` 而不是 `< 0.18`。

## 9. 评分

| 项 | 权重 | 算法 |
|---|---|---|
| 距离 | 40% | `(距离/身高 − 0.55) / (1.45 − 0.55) × 100`，夹到 0–100 |
| 起跳角 | 15% | `100 − |θ − 38°| × 3.6`，合理区间约 32–45° |
| 蹬伸 | 15% | `ok` 100（峰间隔 <25ms 再 −25）；`reversed` 55；`tie` 70 |
| 摆臂 | 15% | 摆幅 <40° 记 40；`|lag| ≤ 120ms` 记 100，之后每超 1ms 扣 0.25 |
| 落地 | 15% | 100 起扣：后移每 cm −1.8（上限 45）、手撑地 −35、直腿落地 −22、蹲过深 −10 |

缺项的指标不参与加权（分母同步减少），不会因为测不到就当成 0 分。

距离权重最高，因为它是结果；其余四项解释「为什么是这个结果」。
这不是官方评分标准，只是一个把动作拆开看相对强弱的工具。

## 10. 误差来源（界面会如实标注）

| 来源 | 影响 | 处理 |
|---|---|---|
| 斜拍 | 水平距离被透视压缩，可能少算 5–15% | 拍摄建议里要求正侧面、镜头垂直对着跳跃方向 |
| 人占画面 <40% | 厘米类指标误差明显 | 界面标黄提示 |
| 脚尖/脚跟识别不稳 | 起跳/落地时刻偏移，距离直接错 | 统计脚部识别率，低于 90% 提示 |
| 只有身高、没有标尺 | 换算依赖 0.891 这个均值比例，个体差异约 ±3% | 提示「放一把卷尺做标尺校准」 |
| 帧率不足 | 起跳时刻精度下降 | 提示实际采样帧率 |
| 等效重力偏离 981 | 比例尺或机位有问题 | 超出 ±150 提示 |

单目视频没有深度信息，这些误差补不回来。所以界面的原则是：
**能测的说清楚，测不准的标出来，测不到的留空（显示 —），不凑数。**

## 11. 验证方式

两套离线校验，都在 `_verify/`（不进 `prototype/`，不参与部署）：

**几何真值校验** `_verify/gen.mjs`
自己造一副已知真值的侧面骨架序列（身高 1.78m、vx 4.0m/s、vy 2.6m/s、
起跳 2.000s、落地 2.530s），让引擎从关键点反算，再和真值对表：

```
PASS  跳跃距离: 实测 2.19m / 真值 2.23m      (−1.8%)
PASS  起跳角:   实测 33.5° / 真值 33.02°     (+0.5°)
PASS  腾空时间: 实测 0.55s / 真值 0.53s      (+0.02s)
PASS  腾空最高点: 实测 0.36m / 真值 0.34m
PASS  等效重力自检: 实测 978 cm/s² / 真值 981
```

三个用例：`clean`（标准跳）、`fallback`（落地后移 + 手撑地）、
`mirror`（画面翻转向左跳，验证 `dir === -1`）。
另有蹬伸判定三条分支的单测（`ok` / `reversed` / `tie` → 100 / 55 / 70 分）。

**界面渲染校验** `_verify/check-page.mjs`

无头 Edge + CDP 打开 `#longjump`，先断言空态，再注入一份离线结果，
检查指标卡、记录表、时间轴腾空带、小结、画布尺寸、标尺浮条、
1440px 与 390px 无横向溢出，并出截图。

```bash
node _verify/gen.mjs         # 几何 + 评分分支
node _verify/check-page.mjs  # 无头浏览器渲染
```

两个注意点：

- `_verify/longjump-engine.js` 是**运行时自动拷贝**的产物，不要手改。
  引擎 `import './pose-engine.js'` 是相对自身路径解析的，直接引 `prototype/` 里那份
  会去加载真的 MediaPipe（Node 里跑不起来），所以 `gen.mjs` 每次先把引擎拷到
  `_verify/`，让它 import 到同目录的桩 `pose-engine.js`。
- `check-page.mjs` 需要本机有 Edge 和 Python，默认路径不在标准位置时用环境变量指定：
  `PYTHON=/path/to/python EDGE=/path/to/msedge.exe node _verify/check-page.mjs`。

## 12. 版权与参考

立定跳远模块为原创实现，没有复制第三方项目代码。用到的公开知识：

- **人体测量学比例**：鼻尖到踝 ≈ 0.891 × 身高，出自 Drillis & Contini 的人体测量学数据，
  与投篮、跳绳模块共用同一口径；
- **MediaPipe Pose Landmarker**：Google 开源，Apache-2.0，模型文件随页面分发；
- **起跳角理想区间 32–45°、峰值取 38°**：来自立定跳远的公开训练资料与
  弹道学的定性结论（人的蹬伸有方向性，最优角低于纯抛体的 45°）。
  具体数字是本项目自己定的经验值，不是引用某个研究的实测分布。

评分公式、阈值、权重都是本项目自行设计的经验参数，
用来说明「动作哪一段相对弱」，不作为竞技判定依据。
